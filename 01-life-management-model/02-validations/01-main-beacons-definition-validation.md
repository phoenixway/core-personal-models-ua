# ✅ VALIDATION — MAIN BEACONS DEFINITION

👉 Мета:  
швидко перевірити,  
чи рівень `main beacons` справді достатньо визначений,  
щоб бути опорою для наступних рівнів,  
а не просто списком красивих формулювань

---

## 1. ЧИ СПРАВДІ ВИЗНАЧЕНО СПИСОК ГОЛОВНИХ ОРІЄНТИРІВ?

- [ ] існує явний список головних орієнтирів
- [ ] список не розмитий і не відкритий без меж
- [ ] орієнтири не дублюють один одного по суті
- [ ] кожен орієнтир реально претендує на статус головного
- [ ] список не перетворився на хаотичний каталог усього важливого

👉 якщо ні → рівень невалідний

---

## 2. ЧИ КОЖЕН ОРІЄНТИР МАЄ СУТЬ?

Для кожного головного орієнтиру:

- [ ] є коротка зрозуміла суть
- [ ] формулювання не є лише красивим слоганом
- [ ] зрозуміло, про що цей орієнтир насправді
- [ ] його можна відрізнити від інших головних орієнтирів
- [ ] він не розчиняється в загальних словах типу “жити добре”, “бути кращим”, “бути ефективним”

👉 якщо ні → рівень невалідний

---

## 3. ЧИ Є WHY / ЧОМУ ЦЕ ГОЛОВНИЙ ОРІЄНТИР?

Для кожного головного орієнтиру:

- [ ] записано, чому це справді головне
- [ ] why не декоративне і не формальне
- [ ] зрозуміло, чому зрада цього орієнтиру була б серйозною втратою
- [ ] why пояснює вагу орієнтиру, а не просто повторює його назву
- [ ] why реально допомагає втримати орієнтир у пріоритеті

👉 якщо ні → рівень невалідний

---

## 4. ЧИ Є SUCCESS SHAPE?

Для кожного головного орієнтиру:

- [ ] описано, як виглядає успіх по суті
- [ ] success shape не зводиться до абстрактного “реалізувати орієнтир”
- [ ] success shape не переплутаний з повною програмою реалізації
- [ ] success shape дає зрозуміти, до чого взагалі йде цей орієнтир
- [ ] по success shape можна приблизно оцінювати правильність руху

👉 якщо ні → рівень невалідний

---

## 5. ЧИ Є FAILURE SHAPE?

Для кожного головного орієнтиру:

- [ ] описано, як виглядає провал орієнтиру
- [ ] failure shape не розмита
- [ ] зрозуміло, за якими ознаками видно, що орієнтир реально провалюється
- [ ] failure shape не зводиться до загального “нічого не вийшло”
- [ ] failure shape дозволяє бачити небезпечні траєкторії завчасно

👉 якщо ні → рівень невалідний

---

## 6. ЧИ Є ANTI-GOAL / ЩО ЦЬОМУ СУПЕРЕЧИТЬ?

Для кожного головного орієнтиру:

- [ ] визначено, що є прямою протилежністю орієнтиру
- [ ] визначено, які сценарії, звички або стани йдуть проти нього
- [ ] anti-goal не підмінений просто “поганими речами взагалі”
- [ ] anti-goal допомагає відсіювати неправильні ходи
- [ ] видно, що саме цей орієнтир забороняє або не дозволяє нормалізувати

👉 якщо ні → рівень невалідний

---

## 7. ЧИ Є DECISION IMPACT?

Для кожного головного орієнтиру:

- [ ] зрозуміло, які рішення цей орієнтир реально змінює
- [ ] зрозуміло, що він дозволяє, а що забороняє
- [ ] орієнтир впливає не тільки на настрій, а на вибір дій
- [ ] є хоча б кілька прикладів реальних розвилок або типових ситуацій
- [ ] орієнтир не лишається просто декларацією без управлінського впливу

👉 якщо ні → рівень невалідний

---

## 8. ЧИ НЕ ЛИШИЛИСЯ ОРІЄНТИРИ ТУМАННИМИ?

Для кожного головного орієнтиру:

- [ ] немає критичної розмитості
- [ ] орієнтир не тримається лише на інтуїтивному “ну я приблизно відчуваю”
- [ ] немає відчуття, що формулювання красиве, але неопераційне
- [ ] по орієнтиру можна пояснити, що він змінює в житті
- [ ] орієнтир уже придатний для переходу в realization model або хоча б близький до цього

👉 якщо ні → рівень невалідний

---

## 9. ЧИ Є ПРІОРИТЕТ І ВІДБІР?

На рівні всього списку:

- [ ] головних орієнтирів не надто багато
- [ ] між ними є хоч якась ієрархія або пріоритетне відчуття
- [ ] немає спроби зробити головним усе хороше
- [ ] список витримує питання “що справді головне, якщо ресурс обмежений?”
- [ ] видно, що це не просто список бажаного, а відбір

👉 якщо ні → рівень невалідний

---

## 10. ЧИ НЕ ПІДМІНЕНО ЦЕЙ РІВЕНЬ НАСТУПНИМИ РІВНЯМИ?

- [ ] тут не описується повна модель реалізації
- [ ] тут не будується mandatory core
- [ ] тут не проектується стратегія
- [ ] тут не описується місяць / тиждень / день
- [ ] рівень лишається саме визначенням головних орієнтирів

👉 якщо ні → рівень невалідний

---

## 11. ЧИ ГОТОВИЙ РІВЕНЬ ДО ПЕРЕДАЧІ В `01-main-beacon-realization-models`?

- [ ] для кожного орієнтиру є достатньо матеріалу, щоб думати “як саме він реалізується”
- [ ] зрозуміло, що саме передається вниз
- [ ] немає критичних дір у суті орієнтирів
- [ ] realization model не доведеться будувати на порожньому місці
- [ ] нижчий рівень не блокується через сирість поточного

👉 якщо ні → рівень невалідний

---

## 12. DONE CONDITION

Рівень вважається достатньо готовим якщо:

- [ ] список головних орієнтирів визначений
- [ ] кожен головний орієнтир має суть
- [ ] для кожного є why
- [ ] для кожного є success shape
- [ ] для кожного є failure shape
- [ ] для кожного є anti-goal
- [ ] для кожного є decision impact
- [ ] орієнтири не туманні
- [ ] список не перевантажений
- [ ] зрозуміло, що саме передається в realization models

---

## 13. УМОВНА ГОТОВНІСТЬ

Можна позначити як `CONDITIONAL`, якщо:

- [ ] список головних орієнтирів уже стабільний
- [ ] більшість орієнтирів достатньо визначені
- [ ] лишилися окремі нечіткі місця, але вони не ламають перехід вниз
- [ ] для проблемних орієнтирів є зрозумілий next step
- [ ] є deadline доопрацювання

👉 у такому випадку:

`УМОВНО ГОТОВО ДО: ____`

---

## 14. ОЗНАКИ ПСЕВДОГОТОВНОСТІ

Рівень лише здається готовим, якщо:

- [ ] орієнтири звучать красиво, але не впливають на рішення
- [ ] why формальне або декоративне
- [ ] немає anti-goal
- [ ] немає failure shape
- [ ] немає decision impact
- [ ] realization models довелося б будувати майже з нуля
- [ ] список головних орієнтирів насправді є списком усього важливого
- [ ] формулювання надто туманні для реального використання
