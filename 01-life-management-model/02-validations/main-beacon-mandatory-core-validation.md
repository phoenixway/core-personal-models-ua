# ✅ VALIDATION — ОБОВ’ЯЗКОВЕ ЯДРО ГОЛОВНИХ ОРІЄНТИРІВ

👉 Мета:
швидко перевірити,
чи для кожного головного орієнтиру визначено
не повну бажану програму,
а саме його обов’язкове ядро:
мінімально достатню правильну конфігурацію реалізації

---

## 1. ЧИ НЕ ПРИЙНЯТО ВЕСЬ ОРІЄНТИР ЗА ЯДРО?

Для кожного орієнтиру:

- [ ] ядро не дорівнює всій повній програмі реалізації
- [ ] у ядро не затягнуто все “просто важливе”
- [ ] у ядро не затягнуто все “емоційно сильне”
- [ ] у ядро не затягнуто все “було б добре мати”

👉 якщо ні → рівень невалідний

---

## 2. ЧИ Є ЯДРОВІ ЧАСТИНИ?

Для кожного орієнтиру:

- [ ] виділені окремі частини реалізації
- [ ] зрозуміло, які саме з них є ядровими
- [ ] ядрові частини — це ті, без яких орієнтир ламається по суті
- [ ] ядро відрізнене від периферії і надбудови

👉 якщо ні → рівень невалідний

---

## 3. ЧИ Є ПОЯСНЕННЯ, ЧОМУ САМЕ ЦЕ ЯДРО?

Для кожного орієнтиру:

- [ ] можна пояснити, чому саме ці частини входять у ядро
- [ ] можна пояснити, чому інші частини не входять
- [ ] немає відбору “по відчуттю” без логіки
- [ ] видно, чому без цих частин орієнтир втрачає правильну форму

👉 якщо ні → рівень невалідний

---

## 4. ЧИ Є MINIMUM VIABLE REALIZATION?

Для кожного ядрового елемента:

- [ ] визначено мінімально достатню форму
- [ ] це не ідеал
- [ ] це не максимум
- [ ] це не повна програма реалізації
- [ ] нижче цього вже не можна чесно казати, що орієнтир реалізується

👉 якщо ні → рівень невалідний

---

## 5. ЧИ Є ПОРЯДОК?

Для кожного орієнтиру:

- [ ] база відділена від надбудови
- [ ] зрозуміло, що має бути спочатку
- [ ] зрозуміло, що має сенс тільки після бази
- [ ] немає хаотичного набору ядрових елементів без послідовності

👉 якщо ні → рівень невалідний

---

## 6. ЧИ Є СПІВВІДНОШЕННЯ?

Для кожного орієнтиру:

- [ ] визначено, що має отримувати більшу частку ресурсу
- [ ] визначено, що має отримувати меншу частку ресурсу
- [ ] немає одного елемента, який монополізує весь орієнтир без підстав
- [ ] співвідношення не руйнує саму форму орієнтиру

👉 якщо ні → рівень невалідний

---

## 7. ЧИ Є EXCLUSIONS?

Для кожного орієнтиру:

- [ ] явно визначено, що не входить у ядро
- [ ] добрі, але не обов’язкові речі не маскуються під ядро
- [ ] передчасні частини відфільтровані
- [ ] підсилювачі не переплутані з основою

👉 якщо ні → рівень невалідний

---

## 8. ЧИ Є ОЗНАКИ ПСЕВДОРЕАЛІЗАЦІЇ?

Для кожного орієнтиру:

- [ ] описано, як виглядає активність без забезпеченого ядра
- [ ] видно, як можна помилково подумати, що орієнтир реалізується
- [ ] описані характерні перекоси
- [ ] описані ознаки локальної оптимізації замість правильної реалізації

👉 якщо ні → рівень невалідний

---

## 9. ЧИ Є ПЕРЕДАЧА ВНИЗ?

Для кожного орієнтиру:

- [ ] зрозуміло, що саме передається в стратегічне проектування
- [ ] зрозуміло, що має бути захищено в довгостроковій стратегії
- [ ] зрозуміло, як ядро має ставати видимим у місяці / тижні / дні
- [ ] ядро не залишається ізольованим верхнім документом

👉 якщо ні → рівень невалідний

---

## 10. ЧИ НЕ ПЕРЕТВОРЕНО ЦЕЙ РІВЕНЬ НА ЩЕ ОДНУ СТРАТЕГІЮ?

- [ ] тут не проектуються strategy lines
- [ ] тут не робиться повна ресурсна стратегія
- [ ] тут не формуються задачі
- [ ] тут не описується повна програма життя
- [ ] рівень лишається саме фільтром обов’язкового

👉 якщо ні → рівень невалідний

---

## 11. DONE CONDITION

Рівень вважається достатньо готовим якщо:

- [ ] для кожного головного орієнтиру визначено ядро обов’язкового
- [ ] для ядрових частин є minimum viable realization
- [ ] визначено порядок
- [ ] визначено співвідношення
- [ ] визначено exclusions
- [ ] визначено ознаки псевдореалізації
- [ ] зрозуміло, що саме передається вниз
- [ ] цього достатньо, щоб не проектувати і не планувати “все хороше” як обов’язкове

---

## 12. УМОВНА ГОТОВНІСТЬ

Можна позначити як УМОВНО ГОТОВО якщо:

- [ ] ядро по основних орієнтирах уже зібране
- [ ] лишилися другорядні уточнення
- [ ] немає блокування для переходу в стратегічне проектування
- [ ] є deadline доопрацювання

👉 у такому випадку:
УМОВНО ГОТОВО ДО: [Дата]
